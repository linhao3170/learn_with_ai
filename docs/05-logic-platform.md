## 二十一、业务逻辑分析平台（Sprint 6）

> 主页新增的第二个顶层入口。与「训练关卡 / 项目认知 / 模块卡片 / 设计画布」并列，
> 不是它们的替代 —— 它把已有的业务图谱能力**组织成一条从"投入项目"到"逐段精读"的完整链路**。

### 21.1 流程

```text
用户投入一个项目（样例题库 或 上传 .py/.zip）
  ↓
① 分析项目大小        sizing.py       → L1–L4 + 结构规模（每个数字标来源）
  ↓
② 按大小选处理策略    tiering.py      → 展开几个板块 / 给几个能力点做课程 / 每段几行
  ↓
③ 产出业务板块        modules.py      → 一级业务域 → 二级功能点 → 真实函数（file:行号）
  ↓                                  【无论项目大小，这一步都会产出板块】
④ 点击板块看分析      SectionAnalysis → 板块卡片 13 字段 + 不负责什么 + 能力点核心度排序
  ↓
⑤ 沉浸式学习业务逻辑  walkthrough.py  → 逐段讲稿（第 N 段：标题（起-止 行）+ 重点记什么 + 一句话概括）
  ↓
⑥ 证据与校验          verify.py       → 重读磁盘源码 + 重解析 AST，逐条复核
```

### 21.2 项目大小 → 处理策略（`engine/logic_platform/tiering.py`）

级别**沿用** `business_graph.complexity`（`complexity-1.1`，按 README §5 的结构定义判定），
平台层**只读不改、不二次定级**。级别只决定"讲多少"，**不参与任何事实判定**。

| 级别 | 策略 | 板块 | 课程（沉浸式） | 单课段数上限 | 单段行数上限 |
|---|---|---|---|---|---|
| L1 | 全量展开 | 全部 | 全部能力点 | 24 | 40 |
| L2 | 全量板块 + 全量课程 | 全部 | 最多 12 个 | 20 | 40 |
| L3 | 核心优先 | 全部（证据齐全） | 核心能力点最多 10 个 | 16 | 32 |
| L4 | 核心优先 + 抽样 | 最多 24 个 | 核心能力点最多 8 个 | 14 | 28 |

**三条纪律：**
1. **截断必须可见。** 超出本级预算的能力点不会消失，而是带
   `walkthrough.state = "beyond_budget"` 与中文 `reason`，界面上原样显示
   「超出本级（L3 核心优先）沉浸式课程预算（最多 10 个能力点），本次未生成课程」。
   **少给内容可以，假装给全了不行。**
2. **预算数字是工程常数**，不是从实测数据学出来的 —— 每个响应都带 `caveat`
   写明「标注为待实测校准」。**不许包装成「AI 智能评估项目难度」**（README §5 阈值纪律）。
3. **算不出级别就如实说。** 图谱缺失或构建失败时 `level_known=false`、`level=""`、
   `caveats` 里写清原因，**不回落到某个默认级别还假装正常**。

### 21.3 「AI 出现幻觉了怎么办」—— 四层防线（这是本平台的正面回答）

这是需求里最要害的一问。本项目原有的纪律（README §13.3 三层判定主体分离）在这里扩成四层：

| 层 | 谁产生 | 能否复现 | 防的是什么 |
|---|---|---|---|
| **1 事实层** | AST 规则引擎（`engine/`） | 逐字节可复现 | 事实不由模型产生 |
| **2 讲解层** | 规则引擎；**可选**替换为 LLM | 规则部分可复现 | 措辞可以灵活，事实必须引用 |
| **3 校验层** | `engine/logic_platform/verify.py` | 逐字节可复现 | **抓幻觉** |
| **4 审核层** | 人（教师一票否决） | — | 语义正确性只能人判 |

**第 3 层是"抓"的动作，它做十一项机械复核，每一项都能落到具体文件与行号：**

| 编号 | 检查 | 抓的是哪种幻觉 |
|---|---|---|
| `V01` | 证据文件必须是项目内相对路径 | 泄漏开发机绝对路径（历史事故：1054 处） |
| `V02` | `1 <= start <= end <= 文件总行数` | **编造行号**（比如引用一个不存在第 900 行） |
| `V03` | 存下的摘录与**磁盘上**那几行逐字符一致 | **编造代码**（写一段"看起来像代码"的东西） |
| `V04` | 摘录的 sha256 与存下的哈希一致 | 讲稿或源码被**静默改写** |
| `V05` | 段的 `code_excerpt` 与磁盘源码逐字符一致 | 摘录被"美化"后与校验对象不一致 |
| `V06` | 段引用的函数在 AST 里真实存在且覆盖段行范围 | **编造函数名 / 行范围** |
| `V07` | 声称"第 N 行 return"时 AST 里第 N 行**真有** Return | **编造控制流结论** |
| `V08` | "这是第几个 return"由 AST 重新数一遍 | 数错 / 编造顺序 |
| `V09` | "后面第 a-b 行不会执行"的区间真实存在 | **编造"这段代码不会执行"** |
| `V10` | 每条断言至少带一条非空证据 | 无证据的空话 |
| `V11` | 每条证据必须带**非空摘录 + 哈希** | **空壳证据**（声称有证据但核不了） |

**证据的四个身份字段**（缺任何一个，证据链就不完整）：

| 字段 | 含义 |
|---|---|
| `evidence_id` | 本证据自己的稳定 id（`ev_<12 hex>`，由 `file:start-end` 派生）。教师审核意见挂它，不用数组下标——下标会随段数变化而漂移 |
| `fact_id` | 图谱事实表的 id，行区间与某条事实相交时填上；**匹配不到就是空串，不编 id**（自测断言：非空 `fact_id` 必须真实存在于 `facts[]`） |
| `file` / `start_line` / `end_line` | 项目内相对路径 + 1-based 闭区间 |
| `excerpt` / `excerpt_hash` | 摘录与哈希，校验器拿去和磁盘逐字符比对 |

**关键实现细节（都是刻意的）：**

- **校验器绕开 `ast_cache`，直接从磁盘重读。** 引擎别处都走缓存（按 mtime+size 命中）；
  校验器不走 —— 否则它校验的是"生成时的记忆"，不是文件本身。多一次磁盘读，
  换来的是"这句话**现在**打开那个文件、翻到那一行，还成立"。
- **任何一项失败 → `can_publish=False`**，失败断言标红并带 `reject_reason`，
  **保留原文不删除**（评审要能看到系统抓到了什么）。
  **不存在"错误率低于 x% 就放行"的规则。**
- **LLM 讲解层的产物自己永远拿不到通行证。** `generated_by=llm_draft`，
  状态强制 `needs_review`；而且模型**只能给行号，不许给代码** ——
  合并时摘录一律由引擎从磁盘重读，模型返回的 `excerpt` 字段直接丢弃。
- **发布权在人。** 引擎只报 `verification_passed`（机械复核通过），
  `can_publish` 恒为 `False`；只有教师审核接口能把状态推到 `approved`。
  且**教师确认也覆盖不了机械错误**：复核未通过时，即使教师点了确认，发布仍被拦住。
- **审核绑定 `source_hash`。** 源码一变，旧审核自动 `stale`，
  系统**不会沿用失效的审核结论**，界面上显示「审核已失效（源码变更后必须重新确认）」。

**实测证据（跨四个项目，用 `python scripts/test_logic_platform.py --compare` 一键复现）：**

| 项目 | 行数 | 级别 | 策略 | 板块（总/展示） | 能力点（总/展示） | 课程 | 成员函数 | 机械复核 |
|---|---|---|---|---|---|---|---|---|
| `lab_safety_assistant` | 784 | L2 | 全量板块 + 全量课程 | 5/5 | 29/29 | 12 | 37 | 75 项通过 / 0 失败 |
| `python_dotenv` | 1,112 | L2 | 全量板块 + 全量课程 | 6/6 | 24/24 | 12 | 51 | 216 项通过 / 0 失败 |
| `flask` | 9,513 | L3 | 核心优先 | 12/12 | **54/40** | 10 | 318 | 214 项通过 / 0 失败 |
| `urllib3` | 13,940 | L3 | 核心优先 | 19/19 | **69/40** | 10 | 495 | 216 项通过 / 0 失败 |

> 机械复核的**项数会随检查项增加而变化**（新增 `V11` 后 python_dotenv 从 206 → 216）。
> 引用这个数字时请注明确切的算法版本（当前 `verify-1.0`），不要跨版本比较。
>
> 行数口径见 `structure_rows[].note`（含空行与注释，排除 `__pycache__`/`.git`/`tests`），
> 与 `validation/README.md` 的统计口径一致但统计范围可能不同（那份只数 `src/` 目录）。

**分级分流是实测生效的**，不只是写在表里：

- L2 的 `lab_safety_assistant` / `python_dotenv` **全部**能力点都在展示范围内（29/29、24/24）；
- L3 的 `flask` / `urllib3` 出现**两级截断**，而且都看得见：
  - **能力点预算 40**：flask 真实 54 个只展示 40 个、urllib3 真实 69 个只展示 40 个，
    板块级 `caveats` 里写明「有 14 / 29 个能力点本次未展示」；
  - **课程预算 10**：40 个能力点里只有 10 个能进沉浸式课程，
    其余 30 个逐个带中文理由「超出本级（核心优先）沉浸式课程预算（最多 10 个能力点），
    本次未生成课程。板块分析与证据仍然完整可看。」

**截断看得见**，是分流能被评审验证的关键 —— 少给内容可以，假装给全了不行。

**防幻觉的定向验证：** 把某一段的 `code_excerpt` 替换成一段不存在的代码后，
校验器立刻报 `V05_segment_excerpt` 失败、`can_publish` 变 `False`。
另：同一份源码两次生成 → 序列化结果逐字节一致（跨进程重跑亦然）。

### 21.4 诚实的边界（评审一定会问，主动交代）

**校验器能证明什么、不能证明什么：**

> 它能证明「这句话引用的那段代码**确实存在且逐字符一致**」；
> **它不能证明「这句业务解释是对的」。** 后者只有人能判。
> 所以界面上从不把「机械复核通过」写成「内容正确」。

这一条不是谦虚，是开发过程中**真实踩到的**：第一版生成器自己产出了 4 处事实错误，
而校验器**全部没抓到**（因为它们引用的代码都真实存在，只是解释说反了）：

| 缺陷 | 错在哪 | 怎么修的 |
|---|---|---|
| `if x < 0: raise Error(...)` 被写成「异常被**接住**而不是往上抛」 | 把**抛出**说成了**捕获** | 把 `raise` 与 `try/except` 拆成两种段类型（`KIND_RAISE` / `KIND_EXCEPTION`），措辞分开 |
| `result = self.string[...]`（局部变量）被写成「这一段会**写入状态** `result`」 | 局部绑定 ≠ 对象状态 | `_state_write_targets` 排除 `ast.Name` 目标，局部变量单独措辞 |
| 函数**末尾**的普通 `return` 被写成「**命中这个条件**就直接返回」 | 那里根本没有条件 | 按 `skipped_line_range` 是否存在区分「提前返回」与「收尾返回」 |
| 段标题用了「其他能力（待归类：advance、has_next…）」 | 拿引擎的诚实降级占位名当教学标题 | `_usable_title()` 拒绝 `unconfirmed` 与「待归类」类名字 |

**教训（值得写进答辩）：** 机械校验管住的是**引用层**的幻觉；
**语义层**的幻觉只能靠"生成阶段就不给它编的空间"来减少 ——
即：段类型分得更细、措辞跟着类型走、讲不了就少讲一条。

**另一类被测试抓到的"过度自信"缺陷**（不是讲稿文案，是状态语义）：

| 缺陷 | 后果 | 怎么修的 |
|---|---|---|
| 教师「重置审核」只清了 `human_review`，却把磁盘上那份 `can_publish=True` 原样写回 | **"已重置"的课仍是可发布状态** —— 界面上会显示一份没有教师背书的"已确认"材料 | `_apply_reviews` 的"无审核记录"分支**重算** `can_publish=False`；并加回归断言（重置后必须回到 `needs_review`） |

这一类错误和"事实说错"同样危险：**状态说错了，人就会相信一份不该相信的材料。**
所以接口自测里专门钉了三条：引擎自己不许 `can_publish=True`、
教师确认才可 `approved`、重置必须回到 `needs_review`。

**其余已知覆盖缺口**（写在每份讲稿的 `caveats` 里，不假装覆盖了）：

1. `except` 分支当前**不单独成段**：源码里的错误处理路径只有主路径被讲到；
2. 「知道就行」只对**模块级函数**与 `self.方法()` 做跨能力点指引，
   形如 `reader.read_regex()` 这类库对象上的调用不做指引（引擎没有接收者类型信息，不猜）；
3. 段内同名函数取行号最近的那个（确定性优先），不保证就是运行时真正被调用的那个；
4. 分支真假恒为 `depends_on_scenario` —— **静态分析看不到输入，不替输入下结论**
   （这一点比参考文档更保守：那份文档在带读具体场景时写了「所以这个条件成立」，
   我们不许把举例当结论）；
5. 仅支持 Python；业务板块划分为 `inferred`，核心度排序是**讲解顺序的参考信号**，
   不是「系统识别出了真实核心业务」；
6. **L4（综合设计项目）的分支策略已实现但未被真实数据覆盖。**
   现有四个项目实测级别是 L1–L3：`lab_safety_assistant`（5 个域）/ `python_dotenv`（6 个域）为 L2，
   `flask`（12 个域）/ `urllib3`（19 个域）为 **L3** —— 都够不到 L4 的门限
   （一级域 > 24，且角色 ≥ 3 且外部入口 ≥ 3）。
   所以「L4 的 24 板块 / 8 课程预算」这条路径**只经代码级验证，没有真实项目实测**，
   对外表述时不许说成"已验证支持大型项目"。

### 21.5 后端接口（13 个新路由，应用版本 → `0.5.0`）

| `GET` | `/api/logic-platform/{id}/lessons`、`/lessons/{capability_id}` | 课程索引 / 一课讲稿（**409** = 超出本级课程预算，`detail` 里给理由） |
| `POST` | `/api/logic-platform/{id}/lessons/{cap}/verify` | 重跑确定性校验 |

**存储：** `backend/data/logic_platform/<analysis_id>/`
（`meta.json` / `graph.json` / `analysis.json` / `lessons/*.json` / `reviews.json` / `source/**`）。
元数据里存的是**相对仓库根**的路径，契约里不出现开发机绝对路径。

### 21.6 LLM 讲解层（可选，默认关闭）

**引擎侧零网络调用**，这是被测试强制的：`scripts/test_teaching_coverage.py` /
`test_teaching_card_coverage.py` / `test_design_rubric.py` 里写死了
`FORBIDDEN_IMPORTS = ("requests","httpx","urllib","http","socket","openai","anthropic","random","time","datetime")`。

所以拆成两半：

- `engine/logic_platform/narration.py` —— **契约与把关**（无网络）：构造讲解请求、
  逐条校验模型返回的引用是否落在所属段的行范围内、摘录一律从磁盘重读、合并后重跑校验器；
- `backend/app/services/narration_service.py` —— **真正的出口**（标准库 `urllib`，不新增依赖）。

开启方式（不配就是关闭，接口返回 503）：

```bash
set LWAI_NARRATION_PROVIDER=openai-compatible
set LWAI_NARRATION_BASE_URL=https://your-endpoint/v1
set LWAI_NARRATION_API_KEY=sk-...
# 重启后端（uvicorn 没开 --reload，见 §19.5）
```

**`llm_in_critical_path` 恒为 `false`** —— 关掉讲解层，大小分析、业务板块、
讲稿结构、证据校验**全部照常工作**。这句话可以直接在演示现场关掉开关来证明。
