> 代码入口：`frontend/src/components/logic-platform/EvidenceNote.vue`（新）/ `EvidenceFold.vue`（新）/ `ImmersiveLesson.vue` / `VerificationPanel.vue` / `scripts/check_evidence_fold.mjs`（新）

## 1. 它解决什么（一句话 + 服务哪个教学阶段）

**一句话**：它把业务逻辑分析平台里**最密的那两块**（沉浸式讲稿的逐条断言证据、反幻觉面板的逐项校验明细）从"铺在页面上"改成"**主张常驻、佐证收起**"，并在每块证据前面写清一条**常驻摘要**：「这些行号只证明引用存在，不证明这句解释是对的」——完整口径点得开。

**服务哪个教学阶段**：它服务的是「凭什么这么说」这一半（`docs/05-logic-platform.md` 的六步链最后两步：板块分析 → 沉浸式讲稿）。它**不服务某一个培训阶段，也不改任何教学内容**：讲稿讲什么、校验怎么做、谁能发布，本轮一个字没改 —— 改的是"这些内容第一眼以什么姿态出现"。

据实的增益（起因是实际操作里看到的两个问题）：

- **太密**：一条断言下面挂着 1~4 个 `文件:行号` 按钮 + 置信度 / 生成主体徽章 + 「确认 / 有问题」两个按钮；一屏十段就是几十个按钮，**主结论反而被淹掉**。反幻觉面板同理：25~145 条校验明细直接铺开，占掉半屏以上。
- **边界没写在证据旁边**：平台确实在抓幻觉（`engine/logic_platform/verify.py` 的机械复核、`narration.py` 的模型把关），但"它抓到哪一层、抓不到哪一层"原先只在文档和代码注释里，**看讲稿的人看不到**。于是"引用对得上"很容易被读成"业务解释也是对的" —— 而这正是本项目最不能犯的错（`docs/09-discipline-and-defense.md` §13 的措辞纪律）。

## 2. 不变式（违反任何一条都算 bug，逐条可断言）

1. **摘要常驻、详述收起，但一条不删**：证据口径的摘要留在页面上，完整说明默认收起**且内容仍在 DOM 里**。
   → `scripts/check_evidence_fold.mjs` 的 `A1`（说明存在）/ `A2`（摘要在抽屉体之外）/ `A3`（默认收起）/ `A4`（收起时正文仍在 DOM，且长度 > 300 字）/ `A5`（点得开）；面板侧同款 `C6`。
2. **主张常驻、佐证收起**：断言原文、置信度 / 生成主体 / 已拦截徽章**不随证据折叠** —— 判断该用多严的眼光看这条结论，靠的就是这三个标记。
   → `B9`（被拦截徽章常驻）+ `B4`（教师标注按钮仍在 DOM）+ 走查里既有的 `logic-claim-badge` 一族钩子一个没删。
3. **收起 ≠ 删掉**：折叠用的是 `.drawer-body`（高度归零），**不是 `v-if`**；收起状态下证据按钮、教师标注按钮、校验明细、被拦截 id 的**条数与内容都不变**。
   → `B3`（证据按钮条数与载荷一致）/ `B4` / `C3`（校验明细条数与载荷一致）/ `C11`（被拦截 id 仍在 DOM）。
   **负向对照**：同一个"内容仍在 DOM 里"的断言跑在一个**故意用 `v-if` 收起**的对照组件（`NegativeControlFold`）上，必须 FAIL —— `N1` 实跑确认它会失败，证明这条断言抓得到"静默删除"。
4. **失败默认可见**：被拦截的断言，它的折叠区**默认展开**；校验明细**有失败项时默认展开**；计数徽章、发布闸门、拦截提示**一律常驻**。
   → `B8` / `C8` / `C4`（计数徽章）/ `C5`（发布闸门）/ `C10`（拦截提示常驻）。
5. **折叠不改变任何判定与契约**：没有新增或删除任何下发字段，`data-test` 钩子**一个没改**（只新增折叠自己的钩子）。
   → `docs/07` §17.2 的三次走查（在线两个项目 + 离线）项数与 UI 重设计一轮**完全一致**；`python scripts/build_acceptance_report.py` 13/13 个脚本通过（数字见 `validation/acceptance_latest.md`）。
6. **说明里的每一句都必须对得上代码**（这一条是本轮的自律，也是最容易腐化的一条）：

   | 说明里写的 | 依据（可执行/可读的实现） |
   |---|---|
   | 机械复核检查路径纪律 / 行区间 / 摘录逐字符 / 哈希 / 符号存在 / return 行与序号 / 「不会执行」的区间 / 每条断言至少一条可核验证据 | `engine/logic_platform/verify.py` 的 `CHECKS`（`V01`~`V11`） |
   | 空壳证据按失败处理，不静默跳过 | 同文件 `V11_evidence_checkable` 的分支（注释里写明"否则等于给绕过证据链留后门"） |
   | 模型只给行号、不给代码；行范围必须落在本段内；摘录由引擎从磁盘重读；落不到证据上的条目直接拒绝并留痕；模型返回的代码文本一律丢弃 | `engine/logic_platform/narration.py` 的模块 docstring 四条把关规则 + `apply_narration` 实现 |
   | 引擎永远不会把「可发布」置为真；任何一项失败都不放行 | 同 `verify.py` 的 `apply_verification`（`review["can_publish"] = False`）与 `VerificationReport.finalize`（`failed == 0` 才算机械通过） |
   | 重新校验重读磁盘、不复用上次结论 | `verify.py` 的 `_read_lines`（刻意绕开解析缓存） |
   | 源码一变，人工审核失效（stale） | `backend/app/services/logic_platform_service.py` 的 `_apply_reviews`（按 `source_hash` 判定） |

   → **门禁缺口（如实写出）**：这条**没有机器化断言**。"说明文案是否覆盖了真实机制"目前只能靠人对着上面这张表复核；能自动化的只有"说明存在且能展开"（`A1`~`A5`）。

> 每条不变式后面写清**哪条测试/断言在盯它**；没有断言的不变式等于没有（第 6 条就是没有断言的，如实写在上面）。

## 3. 契约（输入 / 输出）

| 方向 | 契约 / 字段 | 说明 |
|---|---|---|
| 输入 | `ImmersiveLesson` 的 `lesson`（讲稿契约，未改） | 折叠只读它已有的 `segments[].must_remember[].evidence` / `verified` / `reject_reason`，**不新增字段** |
| 输入 | `VerificationPanel` 的 `lesson` / `verification` / `narration-status`（未改） | 折叠只读已有的 `verification.checks` / `counts` / `rejected_claim_ids` / `rejected_segment_ids` |

| 输入（新组件） | `EvidenceFold`：`label` / `count` / `testId` / `hint` / `defaultOpen` | `defaultOpen` 是留给"这里出事了"的口子（拦截 / 失败时由调用方置真） |

- `algorithm_version`：**本功能不适用** —— 它不产出任何判定，也没有自己的版本号；既有的那些（`verify-1.0` / `narration-1.0` / `sections-1.0` / `tiering-1.0` …）**一个都没改**。
- `has_score`：**不适用** —— 折叠不产生任何分数。
- 字段可见性：**不改变任何字段的可见性**（没有新增下发字段，也没有删字段）。学生视图 / 教师视图的差异仍以 `docs/03-contracts.md` §10.5 的可见性矩阵为准。

## 4. 判定口径（可计算的定义）

这里没有"分数"，只有两个**可计算的定义**：

1. **折叠默认状态**：`defaultOpen = false`，**两种例外**——
   - 讲稿：`claim.verified === false`（该断言已被机械复核拦截）→ 默认展开；
   - 面板：本次校验 `failed > 0` → 逐项明细默认展开。
   取值全部来自契约字段，页面不自己判断"严不严重"。
2. **"收起"的定义**：`data-open="false"` + 复用 `style.css` 的 `.drawer-body`（`grid-template-rows: 0fr`，高度归零）。**不是** `v-if`、**不是** `display:none` 之外的内容移除 —— 内容始终在 DOM 里，所以任何"证据必须完整存在"的检查、检索与评审照旧拿得到它。

**已知的假阴 / 假阳**：

- **假阴**：`A4` / `C6` 判的是"抽屉体里的文本长度 > 300 字"。它证明"内容没被删"，**不证明**"内容是对的、是完整的"（例如说明被删掉一半仍可能过）。真正的防线是 §2 第 6 条那张对照表，**靠人**。
- **假阳**：`B2` 断言"所有折叠区默认收起"。若将来某个折叠区因为合理原因默认展开（例如新增一种拦截状态），这条会假失败 —— 那时要按新的口径改断言，**不许把断言放宽成"至少有一个是收起的"**（那等于不再盯任何东西）。
- **口径纪律**：`N1` 是**负向对照**（用 `v-if` 收起的对照组件必须被抓住）。没有它，`B3` / `C3` / `C11` 这三条"内容仍在 DOM 里"的断言可能是永远绿的假断言 —— 本项目把"没有负向对照的检查"视为不算证据（`docs/00-index.md` §3.3 第 6 条）。

## 5. 学生可见性（安全边界）

- ✅ 学生能看到：证据口径的**常驻摘要**（引用存在 ≠ 解释正确）、每条断言下面的折叠区（点开就是 `文件:行号`，再点跳源码）、置信度 / 生成主体 / 已拦截徽章、校验结论与计数、发布闸门、拦截提示，以及点开就有的**完整口径**（机器检查了什么、检查不到什么、还剩哪些幻觉风险、怎么自己核）。
- ❌ 学生**绝不能**看到：正确答案字段、教师种子里的内部 key（`mh_*` 一类）、权重与阈值明细、模式检测器结论、`_inferred_` 这类内部标记。**本功能没有新增任何下发字段**，所以这些边界与改动前逐条相同。
- **文案纪律（本轮新增的一句自律）**：口径说明里**不写内部字段名**。上一轮踩过一次（`docs/07` §16.1 记的"文案里出现 `correct_answers` 字面量导致走查假失败"），本轮写说明时同样避开了字段名字面量：讲的是"可发布"这类**给人看的说法**，不是 `can_publish` 这类键名 —— 面板里既有的 `generated_by = …` 字段回显是**契约回显**（本来就是给定看的），不在此列。
- 渲染层断言：`scripts/browser_clickthrough.mjs` 对**整个 `documentElement.outerHTML`** 做正则的 4 处"不泄漏"断言（含 `correct_answers`）本轮**一个字没改**，实跑仍全绿。

## 7. 诚实边界（做不到 / 算不出来的部分，必须原样显示给学生）

- **"折叠"没有任何像素级检查**：谁更大、间距好不好看、展开动画顺不顺 —— jsdom 不走样式，自查只断言 DOM 行为与文本。**人眼看**才能确认"第一屏确实清爽了"。
- **没有做真实浏览器的交互验证**：本环境里无头 Chromium 起不来（原因见 `docs/06-runbook.md` §19.5），所以"点击展开"是在 jsdom 里派发真实 DOM 事件验证的，**不是**在真实浏览器里点过的。
- **没有做长讲稿的性能验证**：默认载荷是 19 条断言 / 145 条校验项；更大项目（段落上限 24 段、每段 40 条陈述）下"展开全部折叠区"的渲染代价**未实测**。
- **说明文案与真实机制的一致性没有门禁**（§2 第 6 条）：只有一张人复核的对照表。
- **本轮不改变任何判定**：折叠不会让任何一份报告、分数或不变量变样。若有人觉得"折叠之后结果更可信了"，那只是阅读体验变了。

## 8. 待教师 / 待人工提供的数据

- 本功能**不需要教师数据**：它只排布既有内容，不产出判定，也没有种子文件。
- 需要**人**跟着改的只有一处：**新出现一种"必须默认展开"的情况时**（例如新增某个拦截闸门），要么把它接进 `defaultOpen` 的判定，要么在 §4 里如实登记"这一类默认收起" —— **不许悄悄把失败项也收起来**。

## 9. 该功能踩过的坑（复盘点）

- **现象一（自查脚本假红）**：第一次跑自查，`B6`「证据按钮仍能跳源码」与 `B7`「教师确认仍生效」都 FAIL，而按钮明明在 DOM 里、原生 click 也确实到达了按钮（自查脚本里打了 `[debug]` 才看出来）。
  **根因（两个，互相叠加）**：① 用 `h()` 手写 props 时，事件名必须写 `onOpenSource`；写成 `'open-source'` **不报错、也不触发** —— 于是 `emit` 有去无回；② `B7` 的徽章是折叠区的**兄弟节点**（刻意常驻），断言却只在折叠区内部找。
  **修法**：`frontend/evidence-check-entry.js` 里把事件名写成 `onXxx` 并在注释里写明这个坑；`B7` 改成在断言那一行（`segment-bullet`）里找。已在 `docs/08-tech-debt.md` §19.1 登记。
- **现象二（一次性脚本不该留在仓库外面）**：本轮先用一个临时 jsdom 脚本验证，跑通后**立刻**把它提升为常驻检查 `scripts/check_evidence_fold.mjs`（含负向对照），而不是"验证完就删"。
  **理由**：折叠的核心承诺是"收起 ≠ 删掉"，而这条承诺**最容易被下一次重构无声破坏**（谁把 `drawer-body` 改成 `v-if`，界面看起来一样好，纪律却没了）。没有常驻断言，这种回退只能靠人偶然发现。
- **现象三（口径说明会腐烂）**：说明里写的机制（机械复核查什么、模型能干什么）**不在前端**，而在 `engine/logic_platform/` 里。前端文案与引擎行为之间**没有自动同步机制** —— 改引擎检查项时如果忘了改文案，页面就会说错话。
  **本轮的处理**：在 §2 第 6 条建立"说明句子 ↔ 实现位置"的对照表，并在代码注释里逐条标注依据（`ImmersiveLesson.vue` / `VerificationPanel.vue` 的说明常量上方）。**仍是靠人**，已登记进 `docs/08-tech-debt.md` §19.1。
