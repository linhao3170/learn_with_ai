## 1. 它解决什么（一句话 + 服务哪个教学阶段）

**一句话**：它把"打开系统第一眼看到什么、该先点哪个"从「一进来就是训练页的项目头部 + 一条平级的五个页签 + 一屏口径说明」改成「两大核心功能各占半屏 + 未开始的阶段不给入口 + 证据默认收起但一条不删」。

**服务哪个教学阶段**：它服务的入口覆盖 `docs/01-teaching-design.md` §4 的六阶段（含阶段四·五 设计画布 + 六维评审）与业务逻辑分析平台这两块 —— 但**它自己不服务某一个阶段，也不改任何教学内容**：六阶段讲什么、怎么判分、算不出来的维度怎么显示，本轮一个字没改。它改的是**学生 / 教师怎么进入这些内容**：系统主页面回答"这系统能做哪两件事、我该点哪个"，工作区里的五个页签回答"我现在落在哪一阶段"。

据实的增益：

- 学生：第一次打开就知道「怎么教」（培训系统 · 六阶段）与「凭什么这么说」（业务逻辑分析平台）是两块不同的东西，而不是一屏并列的按钮；
- 教师 / 评审：主页面把"哪些阶段已落地、哪些还没做"摊在入口处（与 `docs/07` §16 的完成度表是同一件事），来源依据与口径一条没删、默认收起、点开就有。

## 2. 不变式（违反任何一条都算 bug，逐条可断言）

1. **默认落地页是系统主页面**（`App.vue` 的 `currentView` 初值 `home`），不是训练页。
   → 走查 `默认落地页是系统主页面`（`data-test="home"` 存在）。
2. **未开始的阶段不给入口**：阶段三（流程推演）/ 阶段六（重构挑战）渲染成 `disabled` 的 `data-test="home-stage-todo"`，连箭头图标都不给；只有已落地的阶段（一 / 二 / 四·五）是 `home-stage-entry`。
   → 走查 `主页面六阶段入口与完成度表一致（只有已落地的阶段可点）` —— 它**钉到具体是哪几个 stage key**（可点必须是 `design,module-card,orientation`，未开始必须是 `flow-sim,reconstruct` 且全部 `disabled`），而不是只数个数：只数个数抓不到"把阶段三偷偷标成已落地"；
   **负向对照实跑过**：把 `flow-sim` 的 `status` 临时改成 `done` → 这条断言立刻 FAIL（`可点 4 个（design,flow-sim,module-card,orientation）`）且走查整体 `SMOKE_RESULT: FAIL`，改回 `todo` 后恢复全绿；另由 `两大核心功能都在主页面且都是独立大模块` 盯住"两个核心确实各自是一个顶层模块"。
3. **证据不删，只是收起**：来源依据与口径默认收起，但 5 组依据 + "本次运行的实际来源"整段仍在 DOM 里，点得开、也能再收回去。
   → 走查 `来源依据默认收起（且内容仍完整在 DOM 里）` + `来源依据可以点开` + `来源依据里写了数据来源与还没做的`（必须命中 `acceptance_latest.md` 与 阶段三 / 阶段六 / 还没做）+ `来源依据可以再收起（不占第一屏）`。
4. **默认可见，不白屏**：`[data-layer]` 不带 `.layer-armed` 时就是普通可见元素，只有浏览器真的支持 `IntersectionObserver` 时才武装。
   → **没有自动断言**。靠 `frontend/src/composables/useReveal.js` 的降级分支（`IO_SUPPORTED` 为假时直接返回、不加 `layer-armed`）+ `frontend/src/style.css` 里 `[data-layer].layer-armed` 这个选择器保证。jsdom 走查里断言到的是"内容在 DOM 里"，**不是**"内容可见"（jsdom 不走样式），所以这条目前只有代码分支，暂无机化断言。
5. **工作区内部的判定口径与交互契约不变**：页签分成两组只是排版，`data-test` 钩子一个没改；"先输出后反馈""不打分""未确认字段不参与比对"等契约照旧。
   → 走查第 4.5 节之后的**后面 13 个环节的断言一个字没改**，本轮仍全绿（项数口径见 §6；同一批断言在改动前就在盯这套契约）。
6. **省略 `initial-stage` 时工作区仍落在「训练关卡」**（`TrainingView` 的 prop 默认值是 `training`）。
   → **没有专用断言**。走查只证明了"从主页面点『进入培训系统』→ 工作区挂载（`stage-switcher` 存在）"；**没有一条断言裸挂 `TrainingView` 时的落地阶段**，这条靠 prop 的 `default` 保证。
7. **主页面上的数字只能来自契约或数据源**（当前项目 / 契约版本 / 训练题数 / 业务模块数 / 在线离线模式 / 离线快照候选路径），页面自己不算任何业务结论。
   → 由 `scripts/audit_hardcoding.py --include-frontend` 盯"写死的业务词与硬编码路径"（本轮实跑前端 0 命中，数字见 `validation/acceptance_latest.md`）；它**盯不到**"这个数字算得对不对" —— 那一层由契约校验与数据源模块本身负责。

> 每条不变式后面写清**哪条测试/断言在盯它**；没有断言的不变式等于没有（第 4、6 条就是没有断言的，如实写在上面）。

## 3. 契约（输入 / 输出）

| 方向 | 契约 / 字段 | 说明 |
|---|---|---|
| 输入 | `TrainingView` 的 `initial-stage` prop | 取值 `orientation` / `module-card` / `design` / `training` / `graph`；非法值或省略 → `training`（与改动前一致）。由主页面 emit，`App.vue` 存在 `trainingStage` 里再传下去 |
| 输入 | `HomeView` 的三条事件 | `enter-training(stage)` / `view-analysis` / `enter-logic`。主页面**不预加载**平台数据：分析全部在后端执行，由用户显式"投入项目" |
| 输入 | 数据源（通道未改） | `useDataSource()` 的 `listProjects` / `loadContract` / `mode` / `readProjectFromUrl` / `writeProjectToUrl` / `snapshotCandidates`；`?project=` 深链的读写仍由它负责，页面里不再抄一份路径表 |
| 输出 | 顶层视图切换 | `home`（**默认**）/ `training` / `logic-platform` / `analysis`；主页面自带顶部条，所以不再套 `AppHeader` |
| 输出 | 主页面 DOM 契约（走查用） | `home` / `home-hero` / `home-stats` / `home-core-training` / `home-core-logic` / `home-chain` / `home-stage-entry` / `home-stage-todo` / `home-training-entry` / `home-mini-module` / `home-enter-training` / `go-logic-platform` / `home-evidence-toggle` / `home-evidence-body` / `home-evidence-row` / `home-mode` / `home-load-error` / `home-logic-offline-hint`；工作区顶部条的返回入口 `back-home` |
| 输出 | 工作区 / 平台页的 DOM 契约 | 既有钩子原样保留（`stage-switcher`、`logic-flow-card`、`logic-stage-step` 仍是六条、`logic-mode-banner`），并新增折叠钩子 `stage-scope-toggle` / `stage-scope-body`、`logic-stance-body` |

- `algorithm_version`：**本功能不适用** —— 它不产出任何判定，也没有自己的版本号；既有的那些（阶段一覆盖度、阶段二事实覆盖、设计层六维评审等）**一个都没改**。
- `has_score`：**不适用** —— 主页面不显示任何分数。契约事实条上的题数 / 模块数 / 契约版本是**契约事实**，不是成绩；设计画布的分数在工作区里，不在主页面。
- 字段可见性：本功能**不改变任何字段的可见性**（没有新增下发字段，也没有删字段），只是重新排布既有内容。学生视图 / 教师视图的差异仍以 `docs/03-contracts.md` §10.5 的可见性矩阵为准。

## 4. 判定口径（可计算的定义）

这里没有"分数"，只有两个**可计算的定义**：

1. **六阶段状态**（`HomeView.vue` 的 `TEACHING_STAGES[].status`）：`done` = 已落地（阶段一 / 二 / 四·五）；`todo` = 未开始（阶段三 流程推演 / 阶段六 重构挑战）。取值依据是 `README.md` §0.2 与 `docs/07-status-and-acceptance.md` §16.1 / §16.3 的完成度表 —— **界面与完成度表是同一件事，不是两套口径**。
2. **入口可用性**：`status === 'done'` → 按钮可点，点击后 emit `enter-training` 并落到对应阶段；`status !== 'done'` → `disabled` + `home-stage-todo`，**不写"即将上线"这类话**。

**已知的假阴 / 假阳**：

- **假阳（最危险）**：把没做的说成做了。只要有人先把 `status` 改成 `done`、或先补一个按钮，界面就会撒谎。当前防线只有"人跟着改"（见 §8），**没有**"界面表 vs 文档表"的一致性断言。
- **假阴**：把已落地的阶段显示成"未开始"。门禁缺口与上一条同源 —— 走查只盯"未开始的都没按钮"与"可点的至少 3 个"，不认具体是哪三个。

**措辞纪律**：界面写"未开始"就只写"未开始"（该行连箭头图标都不渲染）。平台页在离线时的态度同样是"不假装"：主页面卡片里三句立场一句不少，另加一条离线提示 —— **但"进入"按钮不禁用**，点进去由平台页自己显示离线横幅（大小定级 / 板块划分 / 沉浸式讲稿全在后端，前端不自己编一份看板出来）。

## 5. 学生可见性（安全边界）

- ✅ 学生能看到：定位一句话、项目切换器（含在线 / 离线模式徽章）、契约事实条（当前项目 / 契约版本 / 训练题数 / 业务模块数）、两大核心模块与六阶段状态（已落地 / 未开始）、次级入口（业务图谱 / 函数级分析详情），以及**点开就有的**来源依据抽屉（数据来源 / 结论怎么算 / 判分边界 / 验收与门禁 / 还没做的 / 本次运行的实际来源）。
- ❌ 学生**绝不能**看到：正确答案字段、教师种子里的内部 key（`mh_*` 一类）、权重与阈值明细、模式检测器结论、`_inferred_` 这类内部标记。**本功能没有新增任何下发字段**（它只重排既有内容），所以这些边界与改动前逐条相同。
- 渲染层断言：走查 `DOM 中不含 correct_answers 字段名`（对**整个** `documentElement.outerHTML` 做正则，脚本里共 4 处同款）；另有阶段一 / 二 / 四的"反馈区提交前不渲染""页面不给分数"等断言，本轮**一个字没改**。

## 7. 诚实边界（做不到 / 算不出来的部分，必须原样显示给学生）

- **像素级排版没有任何自动检查**：谁更大、间距好不好看、层级是不是真的"一眼看得出优先级"—— 走查只断言 DOM 结构与文本（jsdom 不测样式）。也就是说"两大核心各占半屏"这句话在断言里只等价于"两个模块都在 DOM 里"，**没有任何一条断言能证明它真的占了半屏**。
- **动画只在真实浏览器里才跑**：jsdom 环境既不武装 `[data-layer]`、也不执行 CSS 动画与媒体查询。"链式拉动 / 层进式展现"的效果、方向、时序，走查全绿**不能**作为证据 —— 那必须人眼看。
- **本轮没有做动画的性能与低端机验证**：没有测帧率 / 帧时间 / 移动端设备；`will-change` 与 `filter: blur` 在低端机上的代价未实测，`prefers-reduced-motion` 的关闭效果也没有在真机上验过。
- **六阶段状态表的一致性没有门禁**：`scripts/verify_docs.py` 不解析这张表，"界面写的"与"文档写的"是否一致**只能靠人**（见 §8）。
- **本功能不改变任何判定**：重排界面不会让任何一份报告、分数或不变量变样。若有人觉得"重设计之后结果变好了"，那一定是别的原因。

## 8. 待教师 / 待人工提供的数据

- 本功能**不需要教师数据**：它只排布既有内容，不产出判定，也没有种子文件。
- 需要**人**跟着改的只有一处：`frontend/src/views/HomeView.vue` 里的六阶段状态表（`TEACHING_STAGES[].status`）。阶段三 / 阶段六真落地时必须把对应的 `todo` 改成 `done`，依据是 `docs/07-status-and-acceptance.md` §16.1 / §16.3 与 `README.md` §0.2 —— **不许只改界面不改文档，也不许只改文档不改界面**。
- 同一处纪律的另一半：来源依据抽屉里"还没做的"那一组文案（`EVIDENCE_GROUPS`）与 `README.md` §0.2 的"未开始"清单是同一件事，由人同步。它是写给评审看的诚实边界，不是装饰。

## 9. 该功能踩过的坑（复盘点）

- **现象**：新写的"判分边界"文案里出现了 `correct_answers` 这个字段名（写成"答案（`correct_answers`）不下发"这种**禁令句式**），结果 `scripts/browser_clickthrough.mjs` 那条 `DOM 中不含 correct_answers 字段名` 直接判 **FAIL** —— 页面明明没有泄漏任何字段。
  **根因**：那条断言是**对整个 `documentElement.outerHTML` 做正则**的，它无法区分"泄漏了字段"与"只是在文案里提到了字段名"。（同一类坑 `docs/08-tech-debt.md` §19.4 已经记过一次：Vue 会把模板注释渲染进 DOM，注释里写字段名同样会让断言假失败。）
  **修法**：把页面文案改成不含该字段名的说法（"正确答案不下发到学生视图，前端既不持有、也无法推断对错"），**没有去放宽那条断言** —— 断言宁可粗糙，也不该被文案牵着走。
  **补了什么检查**：没有新增检查（那 4 处正则断言本来就在跑）；补的是**文案纪律**：学生可见文案里不许出现内部字段名。已在 `docs/08-tech-debt.md` §19.1 登记。
- **第二坑（改默认落地页引起的）**：走查原来一 mount 就断言训练页。默认落地页一改，那批断言会因为"训练页还没挂载"而**假失败**。修法是让走查按**真实用户路径**走：先断言主页面（第 4.5 节），再点进培训工作区，**后面 13 个环节的断言一个字没改**。教训：改默认落地页等于改所有走查断言的**前置状态** —— 这不是"排版改动"，是动线改动。
- **第三个（小的，但是刻意的取舍）**：走查**不断言像素尺寸**。"谁更大"在 jsdom 里根本测不出来，写下去只会得到一条永远绿或永远红的假断言。用"谁在里面"断言排版优先级，是这一轮明确接受的口径损失（见 §7 第一条）。
